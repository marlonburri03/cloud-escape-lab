Architekturkonzept

Trennung zwischen stabiler Plattform und fachlich wechselnden Escape-Room-Inhalten.

EbeneRolle
BootstrapVoraussetzungen für automatisierte Deployments
Plattform-StackNetzwerk, Security, zentrale Plattformdienste
Theme-StackEinzelner Escape Room mit eigenen Ressourcen

➡️ Theme-Stacks nutzen nur definierte Outputs des Plattform-Stacks — die Basis bleibt stabil.

Betonen: Erweiterbarkeit für zukünftige Escape Rooms, ohne bestehende Architektur zu gefährden.

Azure Big Picture

Hub-and-Spoke: Connectivity Subscription (Contoso Landing Zone) + Escape-Room-Subscription

Ingress/Egress via zentrales Application Gateway / Azure Firewall erklären. Policies der Landing Zone als Guardrails erwähnen.

Werkzeuge

Git- & Delivery-Flow

main
 ├── feature-<beschreibung>
 ├── fix-<beschreibung>
 └── hotfix-<beschreibung>

Entwickler → Merge Request (Lint & Security) → main → Pipeline: Plan → Apply → Build → Scan → Deploy

Secretless Deployment via OIDC Federated Credentials. Releases über Tags (MVP, MLP, MMP).

Betonen: Pipeline als technisches Merge-Gate, keine manuellen Portal-Änderungen.
